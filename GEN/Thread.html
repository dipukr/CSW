Thread

A thread of execution is the smallest sequence of programmed instructions that can be managed independently by an OS scheduler. Threads of a process share its executable code and the values of its dynamically allocated variables and non-thread-local global variables at any given time.

Local primitive variables are thread-safe because each thread has separate stack memory; local reference variables are not, because each thread shares heap memory. Each thread has its own stack (program counter and local variables)
but shares the same code and heap with the rest of the process.

Process vs Thread

A process is the container: the operating system gives it memory and resources.
A thread is the worker: a sequence of instructions running inside that container.
Every process has at least one thread, and a process with several threads can do several things at once.

  • Definition
    Process: a program in execution.
    Thread: a path of execution inside a process.
  • Memory
    Process: its own virtual address space that no other process can touch.
    Thread: shares the address space of its process.
  • Owns
    Process: a process ID, heap, code, open files and sockets, environment and security context.
    Thread: only its stack, program counter and CPU registers.
  • Scheduling
    Process: not scheduled itself; its threads are.
    Thread: scheduled by the operating system onto a CPU core.
  • Creation Cost
    Process: high, because memory mappings and resources must be set up.
    Thread: lower, because only a stack and scheduling data are needed.
  • Context Switch
    Process: expensive, because the address space changes and CPU caches go cold.
    Thread: cheaper, because the address space stays the same.
  • Communication
    Process: through the operating system, using pipes, sockets, files or shared memory segments.
    Thread: directly, by reading and writing shared objects.
  • Data Safety
    Process: isolated by default.
    Thread: needs locks, atomics or immutability.
  • Failure Impact
    Process: a crash stays inside that process.
    Thread: an OutOfMemoryError or System.exit() ends every thread in the process.
  • In Java
    Process: each JVM is a process; start others with ProcessBuilder.
    Thread: Thread, ExecutorService or virtual threads.

Shared vs Per-Thread Memory

  • Heap
    Shared by all threads: every object and array.
  • Method Area
    Shared by all threads: loaded classes, code and static fields.
  • Open Files and Sockets
    Shared by all threads: handles that any thread of the process can use.
  • Stack
    Private to each thread: method frames, local variables and parameters.
  • Program Counter
    Private to each thread: the instruction the thread runs next.
  • ThreadLocal
    Private to each thread: a separate copy of a value for every thread.

Anything on the heap can be reached by several threads at once, so it needs synchronization.
Local variables live on the stack and are safe without it.

Platform Thread vs Virtual Thread

A running JVM is one process with many threads. Besides the main thread that runs your code, it starts threads for garbage collection and JIT compilation, and a server such as Spring Boot adds a pool of request-handling threads. Those threads come in two kinds since Java 21:

  • Managed By
    Platform: the operating system.
    Virtual: the JVM.
  • Mapping
    Platform: one-to-one with an OS thread.
    Virtual: many virtual threads run on a few platform carrier threads.
  • Stack
    Platform: a fixed reservation, often around 1 MB.
    Virtual: small, and grows on the heap as needed.
  • How Many
    Platform: thousands.
    Virtual: millions.
  • Blocking I/O
    Platform: holds the OS thread while waiting.
    Virtual: unmounts, freeing the carrier for other work.
  • Best For
    Platform: CPU-heavy work.
    Virtual: many concurrent tasks that mostly wait on I/O.

Choosing Between Them

  • Isolation From Crashes
    Separate processes, such as browser tabs or microservices.
  • Running Untrusted Code
    Separate processes, such as plugins or sandboxes.
  • Independent Deployment and Scaling
    Separate processes, such as one service per container.
  • Fast Cooperation on the Same Data
    Threads in one process, such as several workers updating one cache.
  • Many Concurrent Requests
    Threads in one process, such as a web server's request pool.

The trade-off: threads are cheaper and communicate faster because they share memory, and that same sharing is why race conditions, visibility problems and deadlocks exist.

Thread Creation

In Java a thread can be created by extending Thread or by implementing Runnable. The Runnable approach is preferred because it keeps the task separate from the thread and leaves the class free to extend something else.

Calling start allocates a new OS thread and invokes run on it, calling run directly just executes on the current thread with no new thread involved.

void main(String[] args) {
    Runnable task = () -> System.out.println("from runnable");
    Thread t1 = new Thread(task);
    t1.start();

    Thread t2 = new Thread() {
        public void run() { System.out.println("from subclass"); }
    };
    t2.start();
}
Thread Priority

Each thread has a priority and the thread scheduler uses priority to decide which Runnable thread should be allowed
to execute next. Threads with higher priority are executed in preference to threads with lower priority; when two threads share the same priority, the JVM runs them in FIFO order.

Priorities range from Thread.MIN_PRIORITY (1) to Thread.MAX_PRIORITY (10), with Thread.NORM_PRIORITY (5) as the default.

void main(String[] args) throws InterruptedException {
    Runnable counter = () -> {
        String name = Thread.currentThread().getName();
        for (int i = 0; i < 3; i++) System.out.println("{name} {i}");
    };
    Thread high = new Thread(counter, "high");
    Thread low = new Thread(counter, "low");
    
    high.setPriority(Thread.MAX_PRIORITY);    10
    low.setPriority(Thread.MIN_PRIORITY);     1
    
    System.out.println("Main priority: {Thread.currentThread().getPriority()}");    5, the default
    System.out.println("High priority: {high.getPriority()}");
    System.out.println("Low priority: {low.getPriority()}");
    
    high.start();
    low.start();
    high.join();
    low.join();
}
Thread Lifecycle

A thread moves through a defined set of states during its lifetime.

A thread enters Waiting via wait or join and Blocked when contending for a monitor lock.

Once run completes, the thread reaches Terminated and cannot be restarted.

Daemon Threads

A daemon thread is a background thread that does not prevent the JVM from exiting. The JVM shuts down once only daemon threads remain running; user (non-daemon) threads keep the JVM alive until they finish.

Daemons suit background chores like housekeeping, monitoring or garbage collection — never work that must complete or persist data, since they are abruptly stopped at JVM exit.

void main(String[] args) throws InterruptedException {
    Thread monitor = new Thread(() -> {
        while (true) {
            System.out.println("monitoring...");
            try {Thread.sleep(200);}
            catch (InterruptedException e) {return;}
        }
    });
    monitor.setDaemon(true); Must be set before start()
    monitor.start();

    Thread.sleep(500); Main is the only user thread
    System.out.println("main done, JVM exits and kills daemon");
}
  • Shared heap, private stack
    Threads of one process share objects on the heap, so shared mutable data needs locks, atomics or immutability.
    Local variables live on each thread’s own stack and are safe.
  • Prefer Runnable
    Pass a Runnable or lambda to Thread instead of extending it, so the task stays separate from the thread and the class can still extend something else.
  • start(), not run()
    Only start() creates a new thread; calling run() executes on the current one.
    A thread can be started once, and a second start() throws IllegalThreadStateException.
  • Priority is a hint
    setPriority() takes 1 to 10, defaults to the creator’s priority (5 for main) and is never a guarantee of ordering.
    Virtual threads ignore it entirely.
  • Wait with join()
    A thread moves from NEW to RUNNABLE, may pass through BLOCKED, WAITING or TIMED_WAITING, and ends in TERMINATED, use join() to wait for that and remember a terminated thread cannot be restarted.
  • Stop threads cooperatively
    Ask a thread to stop with interrupt() and let it exit cleanly on InterruptedException, rather than swallowing
    the exception or looping forever.
  • Pool your threads
    For many short-lived tasks use an ExecutorService instead of raw threads, and for many blocking IO tasks use virtual threads with Executors.newVirtualThreadPerTaskExecutor.
