Polymorphism

Polymorphism is a mechanism which allows an entity such as a variable, method or object to have more than one form.

Polymorphism enables us to deal with generalities and let the compiler and runtime environment to handle the specific.

Polymorphism can be achieved through method overloading, method overriding and generics.

Polymorphism is the provision of a single interface to entities of different types.

Polymorphism is the use of a single symbol to represent multiple different types.

Many methods can have one common name.

One method can accept many types of arguments.

One method header can be associated with many method body.

One type of reference variable can be used to access many type of objects.

Field level polymorphism: a reference variable of class E can point to objects of class E as well as objects of subclass of E.

Subtype polymorphism is a form of type polymorphism where a variable of a superclass refer to an object of a subclass.

Subtype polymorphism allows a single interface or symbol to represent different type of objects.

Which means code written for a superclass can be used with instances of its subclasses.

At runtime, the program calls the correct method based on the object's actual type.

Inheritance and substitutability - a subclass is considered a subtype of its superclass.

This relationship allows an object of the subclass to be substituted for an object of the superclass.

Dynamic method selection - the specific method that is executed is determined at runtime, not at compile time.

Single Interface for Multiple Types (Polymorphism)

Allows us to write generic, flexible and reusable code that operates on a common superclass or interface while working correctly with any of its subclasses or implementations. Each subclass can provide its own specialized behavior and the appropriate implementation is selected automatically at runtime through dynamic method dispatch, without requiring the calling code to know or depend on the concrete object type.

This promotes loose coupling, extensibility and maintainability, because new implementations can be introduced without modifying existing client code, provided they honor the common contract.

public class Animal {
    public String sound() {return "...";}
}

public class Dog extends Animal {
    @Override public String sound() {return "Woof";}
}

public class Cat extends Animal {
    @Override public String sound() {return "Meow";}
}
void main(String[] args) {
    one reference type, many forms
    Animal[] animals = {new Dog(), new Cat()};
    for (Animal animal: animals)
        System.out.println(animal.sound());
}
Method Overloading

Process of writing multiple methods with the same name in the same class is called method overloading.

Method-overloading is a kind of static polymorphism.

Advantages

AdvantageDescription
Improves ReadabilityMethod overloading increases the readability of the program.
Fewer Names to RecallIt avoids the need to memorize multiple method names.
More Generic CodeMethod overloading makes our code more generic.
Supports Clean CodeMethod overloading supports clean code.
Reduced ComplexityThe complexity of the code is reduced.
Compiler BindingThe compiler binds the method call with an appropriate method body.

Method overloading is achieved by

  1. Argument CountChanging the number of arguments.
  2. Argument TypesChanging the data type of the arguments.
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public double add(double a, double b) {
        return a + b;
    }

    public int add(int a, int b, int c) {
        return a + b + c;
    }
}
How overloading works

All three methods are named add in one class.

They differ by parameter types and count.

The compiler chooses the match based on the arguments.

This is compile-time polymorphism, resolved statically.

Method Overriding

Process of redefining a parent class instance method into its child class to give specific implementation of the parent class method is known as method overriding. Referenced object type, not the reference variable type determines
which method will be called. When we create a parent class reference variable and assign a child class object
then calling an overridden method on that variable will call the child class behaviour.

Key points
  • Final methods can not be overridden.
  • Static methods can not be overridden.
  • Private methods can not be overridden.
  • Child class method is called overriding method.
  • Parent class method is called overridden method.
  • Overridden methods are dynamically dispatched.
  • Finalize method can be overridden to free system resources.
  • Overridden parent class method can be called using super keyword.
  • Runtime polymorphism can be achieved through method overriding.
  • Abstract methods can only be overridden by the first concrete class.
  • The access level cannot be more restrictive than the overridden method.
  • Override annotation denotes that the method overrides the base class method.
public class Shape {
    public String name() {return "shape";}
}

public class Circle extends Shape {
    @Override
    public String name() {
        return "circle";
    }
}

void main() {
    Shape s = new Circle();
    System.out.println(s.name()); 
}
How overriding works

Circle redefines name with the same signature.

@Override tells the compiler to verify the match.

The Shape reference points to a Circle object.

Dynamic binding calls Circle.name() at runtime.
