Concurrency and Multithreading in Operating Systems

Concurrency and multithreading are fundamental concepts in Operating Systems (OS), distributed systems, and modern application development. They allow multiple tasks to make progress efficiently while managing CPU time, memory, and shared resources.

To understand them properly, we need to examine processes, threads, CPU scheduling, synchronization, memory visibility, and concurrency problems.

CPU scheduling and context switching

The operating system schedules runnable threads across available CPU cores.

CPU scheduler

Its responsibilities include selecting runnable threads, assigning CPU time, enforcing priorities and scheduling policies, and balancing tasks across cores.

Common scheduling algorithms include:

AlgorithmDescription
FCFSFirst-Come, First-Served
SJFShortest Job First
SRTFPreemptive Shortest Remaining Time First
Round RobinEach task receives a CPU time quantum
Priority SchedulingHigher-priority tasks are favored
Multilevel Feedback QueueDynamically adjusts task scheduling queues/priorities
Fair SchedulingAttempts to distribute CPU time fairly

Real operating systems use more sophisticated scheduling policies, including fairness and real-time mechanisms.

Context switching

Context switching is the process of suspending one thread and resuming another.

The OS typically needs to preserve and restore thread execution state such as registers, stack pointer, and program counter. Switching between processes may also require changing address-space context.

Context switching has overhead, including scheduler work, cache disruption, and possible translation lookaside buffer (TLB) effects.

Too many runnable threads can therefore degrade performance rather than improve it.

Example: Race condition

Suppose counter = 0, and two threads both execute counter++.

The increment comprises multiple conceptual steps:

Thread A                       Thread B
--------                       --------
Read counter = 0
                               Read counter = 0
Increment local value to 1
                               Increment local value to 1
Write counter = 1
                               Write counter = 1

Expected result: 2
Actual result:   1

counter++ is not an atomic operation.

Example: Java synchronized counter

public class Counter {
    private int count = 0;

    public synchronized void increment() {
        count++;
    }

    public synchronized int getCount() {
        return count;
    }
}

The synchronized keyword provides mutual exclusion and establishes memory-visibility guarantees.

Critical section

A critical section is code that accesses shared state requiring controlled access.

Lock lock = new ReentrantLock();

void update() {
    lock.lock();
    try {
        sharedCounter++; Critical section
    } finally {
        lock.unlock();
    }
}

Mutex vs. Semaphore

A mutex provides ownership-based exclusive locking. A counting semaphore manages a number of permits and can allow multiple concurrent accesses.

For example, a semaphore with three permits can limit access to a database-dependent operation:

Semaphore semaphore = new Semaphore(3);

void execute() throws InterruptedException {
    semaphore.acquire();
    try {
        callDatabase(); At most 3 permit holders execute here
    } finally {
        semaphore.release();
    }
}
Memory model and thread communication

Multithreading requires understanding how writes become visible to other threads.

Modern CPUs use registers, caches, and memory-ordering optimizations. Compilers and runtimes can also reorder operations within the guarantees of their language memory models.

Three important properties are:

  • Atomicity: An operation cannot be observed partially.
  • Visibility: Changes performed by one thread become observable by another under appropriate synchronization.
  • Ordering: Operations are observed according to permitted memory-model rules.

Java example: volatile

public class Worker {
    private volatile boolean running = true;

    public void work() {
        while (running) {
            doWork();
        }
    }

    public void stop() {
        running = false;
    }
}

volatile ensures appropriate visibility and ordering for the flag. However, it does not make compound operations like counter++ atomic.

For atomic increments, use AtomicInteger or suitable locking:

AtomicInteger counter = new AtomicInteger();
counter.incrementAndGet();

The Java Memory Model uses the happens-before relationship to specify when actions are ordered and writes must be visible.

Deadlock and its conditions

Deadlock occurs when threads cannot proceed because they are waiting for resources held by each other.

Four necessary conditions for classical resource deadlock (Coffman conditions):

  1. Mutual Exclusion: A resource cannot be used simultaneously by multiple owners.
  2. Hold and Wait: A task holds resources while waiting for others.
  3. No Preemption: Resources cannot be forcibly taken away.
  4. Circular Wait: A cycle of tasks waits on one another.

Common approaches to avoid or manage deadlocks include global lock ordering, timeouts, minimizing lock scope, deadlock detection, and avoiding nested locking where feasible.

Multithreading implementation in Java

Here is a small example of two threads updating shared data safely.

void main(String[] args) throws InterruptedException {
    AtomicInteger counter = new AtomicInteger();
    Runnable task = () -> {
        for (int i = 0; i < 100_000; i++) {
            counter.incrementAndGet();
        }
    };
    Thread t1 = new Thread(task, "worker-1");
    Thread t2 = new Thread(task, "worker-2");
    t1.start();
    t2.start();
    t1.join();
    t2.join();
    System.out.println(counter.get());
}

Output:

200000

Key observations:

  • start() requests that the JVM start executing the thread.
  • The OS schedules the corresponding native platform threads.
  • Both threads share the same AtomicInteger.
  • incrementAndGet() prevents lost increments.
  • join() waits for both threads to finish.
  • Execution order is not deterministic, but the final result is correct.

Thread pools and task execution

Creating a new OS thread for every task can be expensive. Thread pools reuse worker threads.

Java example:

ExecutorService executor = Executors.newFixedThreadPool(4);
for (int i = 0; i < 10; i++) {
    int taskId = i;
    executor.submit(() -> {
        System.out.println("Task {taskId} executed by {Thread.currentThread().getName()}");
    });
}
executor.shutdown();

Ten tasks are submitted, but at most four pool worker threads execute tasks concurrently. The executor manages queuing and scheduling work onto its workers.

For production systems, queue bounds, rejection behavior, shutdown, and workload characteristics also matter.

CPU-bound vs. I/O-bound concurrency

Understanding workload type is essential when choosing a threading model.

  • CPU-bound
    Tasks spend most of their time executing computations.
    Examples: image processing, compression, numerical calculations.
    Often benefits from parallel execution across CPU cores.
  • I/O-bound
    Tasks spend substantial time waiting for external operations.
    Examples: network requests, database queries, file I/O.
    Often benefits from asynchronous I/O or lightweight concurrency.

For CPU-bound tasks, more runnable threads than available CPU execution capacity can increase contention and context switching without improving throughput.

For I/O-bound tasks, a higher number of concurrent operations can improve resource utilization because some tasks are waiting while others run.

Final mental model

Concurrency is about managing multiple tasks that are in progress. Parallelism is about executing multiple tasks simultaneously. Multithreading is one mechanism for implementing concurrency.

The OS schedules threads, switches execution contexts, and manages resources. Applications use synchronization and memory-model guarantees to make shared-state interaction correct.

For practical systems programming, the most important chain of understanding is:

Threads → Scheduling → Shared Memory → Race Conditions → Synchronization → Memory Visibility → Deadlock → Thread Pools → Performance.

Once these concepts are clear, advanced subjects such as Java concurrency utilities, lock-free data structures, asynchronous programming, and distributed coordination become considerably easier to understand.
